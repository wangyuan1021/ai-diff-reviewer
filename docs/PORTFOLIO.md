# 作品说明

## AI Diff Reviewer

一个可解释、可评测、隐私优先的 Git Diff 风险分析工具。它把确定性的本地规则与可替换 AI Provider 组合起来，把“模型觉得有问题”收敛成可验证的文件、行号、证据、影响和建议。

## 解决的问题

常见 AI Code Review 原型存在三类缺口：自由文本难以消费、模型证据可能指向不存在的代码、完整 Diff 与凭据可能被直接发送或落库。本项目围绕这些失败模式建立约束，而不是只包装一次模型调用。

## 工程亮点

- **证据约束**：严格 Zod Schema、真实文件校验和新文件行号校验，过滤无依据的 AI 风险。
- **隐私边界**：Provider 调用前进行路径匿名化和敏感信息脱敏；SQLite 与 Markdown 不保存原始 Diff 或 hunk。
- **可靠任务**：SSE 实时进度、取消信号、Provider 超时、端到端超时和终态保留策略。
- **可替换模型**：Mock、OpenAI-compatible 与 Ollama 使用统一接口，无 API Key 也能开发和演示。
- **可重复评测**：16 个完全虚构的最小样本，确定性检查规则和脱敏召回，不依赖外部模型。
- **可交付部署**：多阶段 Docker、Nginx 同源代理、SQLite 数据卷、健康检查和 GitHub Actions。

## 质量证据

- `pnpm check` 覆盖 ESLint、TypeScript、Vitest/Supertest、生产构建和 HTTP 冒烟链路。
- `pnpm eval` 当前验证 16/16 样本、26/26 预期规则和 7/7 敏感类型。
- CI 同时验证代码质量、评测报告未漂移，以及 Server/Web 两个容器目标可构建。

## 技术取舍

- MVP 使用 SQLite 与内存任务队列，获得低部署成本；多实例生产环境应替换为共享数据库与外部队列。
- 使用非流式模型响应简化严格 JSON 校验；SSE 流式传输的是可控任务进度而非未校验 token。
- 基于模式的脱敏降低泄露风险，但不能承诺识别所有秘密或个人信息，因此外部 Provider 仍需数据分类和人工复核。

## 可继续演进

- 增加真实项目上的盲测集、精确率与误报分析。
- 引入团队级规则配置、基线抑制和风险接受审计。
- 接入 GitHub/GitLab PR 评论，并保持证据校验和最小数据发送原则。
- 为生产多实例部署引入持久任务队列、鉴权、配额与可观测性。
